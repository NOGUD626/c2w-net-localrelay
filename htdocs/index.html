🌐 コンテナ on WASM (ネットワーク有効)

🚩 PoC: ブラウザの中の Linux から外と通信する

右のターミナルはブラウザの WebAssembly 上で動いている Alpine Linux (RISC-V) です。 さらに、ホスト Mac で常駐させている c2w-net が L2 イーサネットフレームを WebSocket で受けて、ホスト OS の本物 socket() で外に出す ので、コンテナ内から wget / ping / nslookup がそのまま使えます。

まずは起動確認

  • uname -a
    動いているカーネルを表示 (RISC-V Linux)
  • ip addr
    eth0 に 192.168.127.3 が付くはず (c2w-net の DHCP)

ネットを叩いてみよう

  • cat /etc/resolv.conf
    DHCP で配られた nameserver (= c2w-net ゲートウェイ) を確認
  • dig google.com
    詳細な DNS 情報 (Mac のシステムリゾルバに forward される)
  • ping -c 3 8.8.8.8
    ICMP も gvisor-tap-vsock が終端 → Mac の ping として外へ
  • curl -sS http://example.com/
    HTTP plain text を取得
  • curl -sS https://api.github.com/zen
    ★ HTTPS は CA 入りの curl で証明書検証込みで通る

エディタで遊ぼう

  • nano --version
    nano 8.0 が入っている (本体起動は nano /tmp/hello.txt)
  • apk info | head -20
    インストール済みパッケージ一覧 (apk は使える状態)

仕組み

なぜブラウザで Linux が動くの？
CPU エミュレータ TinyEMU (RISC-V) を WebAssembly にコンパイルし、その上で Linux カーネルとコンテナの rootfs を起動しています。1 つの out.wasm に エミュレータ・カーネル・rootfs がすべて同梱されています。
L2 がブラウザから外に出ていく経路は？
ゲスト Linux の eth0 (virtio-net) から出た L2 フレームを TinyEMU が取り出し、 ws-delegate.js が ws://localhost:8888 へバイナリ送信。 ホスト側 c2w-net が gvisor-tap-vsock でユーザー空間 TCP/IP 終端し、 Mac の本物 socket() で外部へ抜けます (アドレス: ゲートウェイ 192.168.127.1、ゲスト 192.168.127.3)。
ブラウザの Fetch モード (?net=browser) との違いは？
Fetch モードはホスト不要だが HTTP/HTTPS かつ CORS OK なエンドポイントだけ。 本 PoC の delegate モードはホスト側 c2w-net が要るが TCP/UDP/ICMP 何でも、CORS 制約なし。 ping や ssh も通る。
